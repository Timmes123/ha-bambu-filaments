# HA-Bambu-Filaments

Custom Home Assistant integration ("Bambu Filaments", domain `bambu_filaments`) that surfaces the Bambu Lab cloud Filament Manager (spool inventory from Bambu Studio 2.6.1+/Handy) in Home Assistant. Will be published on GitHub (account: **Timmes123**, repo `ha-bambu-filaments`, public, MIT) and installed via HACS as a custom repository.

Authoritative documents:
- `RESEARCH.md` — API research (endpoints, auth, schemas, risks). Factual basis; verified 2026-08-27.
- `SPEC.md` — agreed design (architecture, entities, phases). Keep updated when decisions change.

## Release policy (since v1.0.0)

**All releases after v1.0.0 are GitHub prereleases** (`gh release create --prerelease`), exactly like ha-better-todo — UNLESS the user explicitly asks for a stable release. HACS installs prereleases fine when downloading a pinned version. Version numbering continues normally (1.0.1, 1.1.0, …).

## Hard rule: deployment only via HACS releases (same as ha-better-todo)

No direct file deployment into the live Home Assistant (`ha_write_file` for integration code is forbidden). Develop locally → commit → bump `manifest.json` → tagged GitHub release (`gh` CLI at `C:\Program Files\GitHub CLI\gh.exe`, not on PATH) → update via HACS → restart HA → verify via MCP (read-only). Once the repo exists, mirror ha-better-todo's release setup (zip_release, draft-with-asset flow).

## Security rules for this project

- Never ask for, read, echo, or store the user's Bambu password/tokens in chat, files tracked by git, or logs. The Phase-0 script prompts interactively; the token cache stays local and gitignored.
- Diagnostics in the integration must redact tokens, RFIDs, device serials.

## Dev environment & runbook (for future sessions)

- Local `.venv` (Python 3.14) has: curl_cffi, pillow, playwright (+ chromium), homeassistant==2026.8.3 for import smoke tests. Node 24 available for JS syntax checks (`node -e "new Function(require('fs').readFileSync(...))"`).
- **Release pipeline** (every change): bump `manifest.json` version (BOM-free write!) → commit/push → wait for CI green → `git archive -o bambu_filaments.zip <tag>:custom_components/bambu_filaments` → `gh release create <tag> bambu_filaments.zip --draft [--prerelease]` → `gh release edit <tag> --draft=false` → delete local zip (it is gitignored, but one slipped into a commit once) → `ha_manage_hacs update_information` + `download version=<tag>` (repo id 1348396125) → `ha_restart` (the MCP "connection lost" error on restart is EXPECTED and means it worked) → wait ~2 min → verify via `ha_get_logs`/`ha_search`.
- **Screenshots**: `python tools/screenshots/take_shots.py` (harness.html mocks hass + ha-card/ha-icon; Playwright element shots into `images/`). Re-run whenever card visuals change; README embeds absolute raw.githubusercontent URLs.
- **API probes**: `tools/.bambu_token.json` (gitignored) caches the user's ~90-day cloud token from phase 0 — reusable for read probes and self-cleaning write probes with curl_cffi (`impersonate="chrome"`). Never handle the user's password; they run interactive logins themselves.
- **PowerShell 5.1 traps**: double quotes INSIDE here-string arguments to native exes (git -m, gh --notes, python -c) get mangled and split the argument — write multi-line python to a script file instead, and keep commit messages/release notes free of `"`. A failed `git commit` followed by `git tag` pushes a tag pointing at the OLD commit — fix with `git tag -f` + `git push -f origin <tag>`. `Set-Content -Encoding utf8` writes a BOM (hassfest rejects it) — use `[System.IO.File]::WriteAllText` with `UTF8Encoding($false)`.
- Live HA facts: printers A1 Mini + A2L (each with AMS) via the Bambu printer integration (cloud mode); our config entry logged in by the user; dashboard "Filamente" at `/bambu-filamente/spulen` (two card variants, combine on, low-stock filter 200 g); HA auto-mode classifier may block HACS/dashboard write tools — if denied twice, stop and ask the user instead of working around.
